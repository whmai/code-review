# 回退残留清理门禁

当用户要求代码回退/回滚，且文件看起来已恢复但 Git 仍显示修改时，目标是只清除已经确认不应存在的差异，绝不覆盖仍需保留的工作。

1. 明确回退基线（`HEAD`、提交、分支或暂存区）；目标不明确时只检查和报告。
2. 分别检查工作区相对暂存区、暂存区相对目标基线的差异，识别空白、行尾、编码/BOM、文件模式、可执行位、格式化或生成文件等原因。
3. 仅当用户明确要求文件完全回到已确认基线，且没有待保留的局部改动时，才精确恢复该单个文件的内容和模式。
4. 部分回退或混合改动必须保留并报告；不猜测用户想保留什么。
5. 禁止 `git reset --hard`、批量恢复或影响未指定文件的命令；处理暂存区前必须明确是否也要撤销暂存。
6. 修正后重新检查工作区和暂存区，只有目标文件相对指定基线均无差异时，才能报告 Git 已不再标记该文件。

审查记录要包含目标基线、原始状态、差异原因、工作区/暂存区处理和最终差异检查。
