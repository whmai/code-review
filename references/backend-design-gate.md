# 后端设计与可维护性门禁

## 项目惯例、文件放置与复用

- 先比对相近功能的目录、分层、命名、模块接口、调用链、错误处理和日志格式；项目已有惯例优先于个人偏好。
- 新文件放在职责对应且与相似代码一致的位置。不要为方便把领域逻辑塞进 Controller/UI、工具包或随机目录；结构不适用时说明原因和替代位置。
- 只在语义、事务、权限、错误语义和性能约束一致时复用或以小而内聚的参数扩展。避免万能方法、参数/布尔标志膨胀、分支堆砌和重复实现。

## 模块、接口与模式

- 对真实变化点设计深模块：以小而清楚的接口隐藏编排、校验、重试和细节。不存在变化或替换需求时，不引入仅供形式的 seam、Strategy、Factory、Adapter 或 Template Method。
- 领域规则不散落在 Controller/UI 或多个调用点；不跨层复制校验、映射、查询或异常转换。公共接口说明输入、错误、幂等性、顺序和性能约束。

## 注释、日志、工具、常量与选项

- 注释解释业务不变量、取舍、兼容性、并发/事务陷阱或外部约束；不复述显而易见代码。
- 关键写入、异步任务、外部调用和故障路径使用项目结构化日志、指标或追踪，包含关联 ID、脱敏业务键、结果/错误类别和耗时；不记录敏感数据或在循环中刷噪声日志。
- 可跨调用方复用、无状态且业务无关的纯逻辑先检索公共工具模块；没有合适能力才在项目约定位置新增。单一调用方或强业务耦合逻辑不应过早塞进全局 Utils。
- 稳定重复值使用有业务名称的常量；部署配置、密钥和运营配置走配置机制。同领域常量和类型按项目惯例集中，避免魔法字面量和万能常量文件。
- 封闭稳定的业务选项使用枚举/受限领域类型并直接引用；动态选项使用受校验配置/注册表。改动公共工具、常量或枚举时验证 API/存储兼容性、默认与未知值处理。

## 通过标准

| 检查 | 通过标准 |
| --- | --- |
| 项目惯例与放置 | 文件位置、分层、命名和职责有相近实现或明确理由。 |
| 复用与接口 | 无无故重复；接口小而内聚；新增抽象有真实变化点和测试收益。 |
| 注释与可观测性 | 必要决策已解释；关键路径可诊断且敏感数据被排除。 |
| 工具与业务类型 | 通用纯逻辑在正确位置；无魔法值；枚举/配置选择与扩展性匹配。 |
